# ADR 0001 — Adoção de Arquitetura Orientada a Eventos com RabbitMQ para Ingestão Assíncrona de Detecções de IA

- **Status:** Aprovado
- **Data:** 10/11/2026
- **Autor:** Robson Stica
- **Contexto da Decisão:** APS 3 — Modelagem de Software (UniSenai) / Projeto SafeLine

---

## Contexto

No sistema **SafeLine**, câmeras de monitoramento transmitem múltiplos fluxos de vídeo em alta resolução (via protocolo RTSP) para o **Motor de Visão Computacional (Python / YOLOv8)**. O motor analisa os frames em tempo real para verificar a conformidade do uso de Equipamentos de Proteção Individual (EPIs — NR-6) e posturas ergonômicas (NR-17).

Caso o Motor de IA realizasse chamadas síncronas bloqueantes (via HTTP/REST) diretamente contra o **SafeLine Core API (Spring Boot)** a cada detecção de infração:
1. Picos de desvios na fábrica (e.g. troca de turno ou início de operação em múltiplos postos simultâneos) causariam esgotamento da *thread pool* do backend HTTP.
2. Qualquer instabilidade de rede ou lentidão transitória no banco de dados relacional faria o motor de IA travar ou descartar frames subsequentes por *timeout*.
3. O acoplamento temporal impediria o controle de vazão (*backpressure*).

Era necessário adotar uma estratégia de integração resiliente, que absorvesse surtos de tráfego, garantisse a persistência confiável dos eventos de telemetria e permitisse o processamento desacoplado das ocorrências de compliance.

---

## Decisão

Adotaremos uma **Arquitetura Orientada a Eventos (EDA)** baseada no message broker **RabbitMQ** (protocolo AMQP 0-9-1) com filas duráveis (`durable queues`) e confirmações explícitas de entrega (`manual acknowledgments`).

O fluxo padronizado de ingestão opera da seguinte forma:
1. O Motor de IA processa o frame, faz upload da evidência no Object Storage (MinIO) e publica imediatamente um evento leve assíncrono `DetecaoEvidenciaEvent` na exchange `safeline.detections` com routing key `detection.epi.deviation`.
2. O RabbitMQ armazena a mensagem de forma durável em disco.
3. Consumidores concorrentes no **SafeLine Core (Spring AMQP / `@RabbitListener`)** drenam a fila de acordo com a sua capacidade de processamento (*Prefetch Count = 20*), persistindo a ocorrência como `PENDENTE_VALIDACAO` no PostgreSQL.
4. Caso ocorram erros de formato ou falha irrecuperável, as mensagens são roteadas para uma **Dead Letter Exchange (DLX)** para posterior auditoria técnica sem perda de dados.

---

## Consequências

> *"Análise crítica de trade-offs: Nenhuma decisão arquitetural é perfeita, todas possuem um preço."*

### Vantagens e Ganhos Técnicos `[+]`
- `[+]` **Resiliência a Picos de Tráfego e Backpressure:** O broker atua como um pulmão de amortecimento (*shock absorber*), evitando a sobrecarga do banco de dados relacional durante rajadas de detecções na linha de produção.
- `[+]` **Desacoplamento Temporal e de Falhas:** Se o backend SafeLine Core estiver indisponível ou em processo de reinicialização para atualização, o Motor de IA continua capturando e enfileirando dados sem perda de evidências críticas.
- `[+]` **Latência Mínima no Pipeline de Visão Computacional:** O worker de inferência de IA não fica bloqueado esperando transações de banco de dados ou chamadas de notificação, mantendo a taxa de frames (FPS) estável.
- `[+]` **Escalabilidade Horizontal de Consumidores:** Facilidade de adicionar novas instâncias consumidoras do Spring Boot para drenar filas em horários de pico operacional sem alterar o produtor de IA.

### Desvantagens aceitas e Débitos Técnicos `[-]`
- `[-]` **Consistência Eventual:** Há um pequeno atraso (geralmente milissegundos a segundos) entre o momento em que a câmera registra o desvio e o instante em que a ocorrência fica visível no dashboard do auditor humano.
- `[-]` **Sobrecarga de Infraestrutura e Monitoramento:** Introduz um componente de infraestrutura com estado (*stateful broker*) que exige clusterização, monitoramento de disco, alertas de comprimento de fila e gerenciamento de Dead Letter Queues (DLQ).
- `[-]` **Complexidade no Tratamento de Mensagens Duplicadas:** Exige implementação de idempotência no SafeLine Core (utilizando o hash do frame ou ID único da detecção) para evitar a criação duplicada de ocorrências em caso de retransmissão de rede.
